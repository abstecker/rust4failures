Rust for Failures

Why Rust?

I fell in love with Rust at the Columbus Rust MeetUp. One night they decided to have everyone pair up and work on Emily Bache's classic GildedRose Refactoring Kata. Both myself and Philip Fried were newbs to the language, so we paired up and went to it. we spent the next hour banging our heads against the wall. It was as if nothing was working. You got rid of one error, and then twelve others would spring up. It's as close to battling a hydra that I've gotten coding.

Then, all of a sudden something clicked, and heaven and earth's mysteries all came together. We were green. We did it. You'd think we'd won the World Cup by the way we were yelling and high-fiving each other. I've never had a greater rush programming in my life.

I warn people, that programming is a lot like the feelings you get as a gambler, chasing that next big win. It's hours and hours of banging your head up against technical walls looking for that moment when you crash though and get to go full on Kool-Aid Man.

Then the pandemic hit.

One of the great things about Rust is that it is a language designed by control freaks for control freaks. Given that we would all be spending a significant amount of time at home, I decided it was time to start working on a project.

I fell in love with poker watching Mike Sexton and Vince Van Patton hosting the World Poker Tour TV show... Chris Moneymaker going up against Sammy Farha at the WSOP Main Event Final Table... and Daniel Negreanu getting crushed by Gus Hansen in the most brutal hand I have ever seen on High Stakes Poker.

As soon as Daniel Negreanu started talking about GTO and Modern Poker Theory, I became fascinated with poker solvers, and rather than buy one, why not try to write one? I mean, what could be so hard that a three time college dropout with a C average in high school math classes couldn't solve?

Plus, there was a siren song that I'd been hearing for a while. A sweet sweet melody that only someone who has truly slaved in the Node.JS salt mines can truly appreciate: WebAssembly. The idea that you could create a library in the brutalist realm of Rust, and then wrap it in some glue and leverage it from the nightmarish hellscape that is the interwebs seemed like a heavenly dream. I had played around with using cffi to create a Python package that reuses a c library, and thought it was a wonderful example of code reuse. Imagine adding to the the ability to create front end JavaScript libraries that were calling from the web the same architected code you created for the back end.

When you get right down to it, Rust is a trauma response from the years and years of defects created by other languages. I am a firm believer in making problems impossible instead of traditional creating controls to prevent them. Rust can create shit systems with the best of them, but by its very design it makes a whole collection of code crimes simply impossible to commit.

Programming languages like JavaScript and Python were never designed to be the source of truth of complex systems. Suddenly, the velocity of code change is accelerating exponentially, and languages designed with flexibility in mind are seeing that feature being used against them. Anyone maintaining systems now is seeing that effect in real time. Security alerts about popular libraries are now a daily occurrence. Agentic coding systems may not be the best at constructing architectural beauty, but they can sure as shit act like a million chaos monkeys.

You see, when I talk about failing as a skill, it's all about controlled failure. Minimizing risk. Python, and other scripting languages like it, are so flexible that the variance they introduce, compounded by the velocity of the coding agents that produce it, creates a terrifying cocktail. Add on to that the fact that many of the people using these systems have no fucking clue what the code they are creating actually does.

Rust, combined with disciplined design and technologies like web assembly, offer a way to simplify and organize what has traditionally been a mess, outside of the exalted chambers of bank mainframe system developers. Not only do I believe that but I intend to prove it.

That doesn't mean that these languages like Python and JavaScript won't play a supporting role in this exercise. One of my favorite returns of investment in the way I have been coding, is how easily I can take my core library and wrap it in Python or Node.JS. How I can use that same single library and create not just one, but several web applications, all using a blob of code that's under 5MBs, and working with the same, battle tested library functioning as a single source of truth.

TBH, this is a bet. For a long time I've felt like the domain surface of complex software systems is much too wide, unorganized, and exposed. It felt like we were building enterprise applications backwards, picking out the tiles for the kitchen before we even decided on the architecture. Now that we are living through the era of agentic coding solutions, we are seeing that risk manifest in real time. Agentic coding systems may not be the best at constructing architectural beauty, but they can sure as shit act like a million chaos monkeys. To be honest, we've been incredibly wasteful and lazy with our resources in the enterprise space. Game developers have to squeeze every last ounce out of their code, but over here we can just spin up more containers comfortable that we were never going to be a Goodle or a Meta, and heck, we're not paying for it anyway. Somebody's got to keep that money hole burning. Now that the music has stopped playing, and the clankers are everywhere sucking up resoures like me at an all you can eat buffet.

Face it, organizations have no choice but to tighten up everything.

SPOILER= ALERT: Fast Foward 6 Years

The success of the experiment is beyond my wildest dreams. I've proven that the pattern at the core of this work can be used as the foundation for a number of different web applications straight from GitHub, without a server required at all. In order for this to work, the library had to be under 10mb, which is crazy to me.

  • A Kuhn Poker app, that is one of the examples used for teaching game theory. You don't have to just read about it, you can actually play it.
  • A GTO style poker ranges ui.
  • A poker table that turns GitHub into a mock casino, where you get to play against bots of different playing styles or just watch them battle it out against each other. I turned GitHub into a casino!!! (Pretend casino... no real money is exchanged... just for funsies!)

The same library is also used for wrappers in

  • Python
  • Node.JS
  • and soon to be Elixir.

Finally, the library is working as the foundation for a server hosting various networked bots, both programmatic and AI driven, as well as human backed clients interfacing with the server through gRPC.

A Revelation

It was the introduction of agentic style of coding through such tools as CoPilot, OpenAI, and Claude Code that really brought clarity to what I was doing. When it first got pushed to be through GitHub's CoPilot, I figured sure, why not? Let's see what they got.

At first it was like an over-eager text completion. I found it very useful for things like the macros that make up the domain-specific language that is used for card ranges like 66+,AJs+,KQs,AJo+,KQo, use in my range tool (Which is still very much a WIP).
