Rust for Failures

The Command Line Perspective - scratch

When I code I like to be able to play with my code. While I am a fanatic about testing, there2 is a fundamental weakness in unit testing: all unit tests are self fulfilling prophecies.As a developer, you need to conceive it, to create it. The thing is, visualizing things is something that can be rather challenging for people. We have so many built in preconceived notions, and compound on top of the fact that the human brain can be very bad at picturing things it has never seen before. This is why I always have a command line perspective on my core libraries.

As a 100x Hackerman (aka lazy), I don't usually want to take the time to write my own command line parser, so I look for the standard for whatever language I am coding in at th moment. For Rust, I would use clap and add it to the library this way:

$> cargo add clap

NOPE! Scratch that. We're writing a library, so we don't want command line parsing to be a part of the dependencies that users download, so let's make it a dev dependency:

$> cargo add clap --dev

This will add the library to our Cargo.toml in a dev-dependencies section:

[dev-dependencies]
clap = "4.6.7"

But, wait a minute. Why are we skipping ahead of ourselves and using a custom library when we haven't even rolled our own? Let's throw away clap and do it ourselves first.

std::env

There are two ways you can approach command line input. The simplest way is to just read the value in from the arguments passed into the program like this:

💾 examples/pkenv.rs · L1–L1 · step 003 of rust4failures · diff · browse

use std::env;

We're importing the std::env module. The Rust Standard Library, std library is going to be your bat utility belt throughout your journey as a Rust developer.3 The Rust core group is insanely well thought out, and a lot of their decisions have been learning from the mistakes of the brave pioneers that went before them.4

I will confess that in my early days as a developer, I spent a lot of time studying the core documentation of the languages I was programming in. Yes, I was one of those assholes that read the Monster Manual and the D&D Dungeon Master's Guide even though I was just a player. You can't find a better collection of free online reading material than what is available for Rust developers.5

std::env is for interacting with the environment our program is running under. One important thing to call out is that we wouldn't be doing that in our actual library. This is just an example program that will be included in the repository. Normally, we would be including this as a part of another executable program as a dependency.

💾 examples/pkenv.rs · L2–L3 · part 2 of 4

fn main() {
    let args: Vec<String> = env::args().collect();

There's a lot going on in this start of this program. You'll have to forgive me if I am going into so much detail, but I want you to get a feel for the devil in the details of this language. Every language has a particular flow to how it works, and it helps a lot once you start to get the feel for it.

fn main() { is the start of every Rust executable program.

Let's break down let args: Vec<String> = env::args().collect():

  • env::args() returns an Args struct.
    • Args implements the Iterator trait.
      • Iterator includes the collect() function
        • collect() returns a generic collection.
  • let args declares an immutable variable. By default, variables in Rust are immutable.6
    • Vec<String> is what we call a type hint. Since collect() returns a generic collection of things, we need to give args a hint as to what we are passing in. TBH, this can be some of the most mind bending aspects of Rust programming... at least to me.

So basically, read in the arguments passed into the program and collect them into a vector of Strings.

std::io

One line in, one reply out

What the program says back doesn't belong in the code that reads and prints. Keep it in a Session that takes a line and returns a line, and anything can drive it: a terminal, a test, a web page.

Session lives in the library, in src/session.rs. That doesn't break the rule from std::env: Session never reads or prints, so the library still knows nothing about terminals. Its code isn't in this chapter; it's in the repository. The library hands it out:

mod session;
pub use session::Session;

$> git checkout step-004-pkio_session

Session also compiles to WebAssembly, so that the same Session can answer in this page. The crate builds a second kind of library for that, a cdylib, and the wasm-bindgen attributes on Session sit behind a wasm feature. Without the feature the crate is plain Rust. wasm-bindgen is an optional dependency for the same reason clap was a dev dependency: users who don't ask for the feature never download it.

A terminal to type in

💾 examples/pkio.rs · L1–L41 · step 005 of rust4failures · diff · browse

use std::io;
use std::io::{IsTerminal, Write};

use rust4failures::Session;

/// For this version of reading a string in from the command line, we are going to
/// us Rust's standard library https://doc.rust-lang.org/std/io/#standard-input-and-output module,
/// which handles input, the i, and output, the o.
///
/// Reading and printing live here. What to say back lives in `Session`.
fn main() -> io::Result<()> {
    let mut session = Session::new();
    // Only a person at a terminal needs a prompt. When the input is piped in,
    // a prompt is just noise in the output.
    let interactive = io::stdin().is_terminal();

    loop {
        // Step 1: Prompt the user for his cards:
        if interactive {
            print!("hand> ");
            // OK this is ugly. This is why I use libraries like `clap`.
            io::stdout().flush()?;
        }

        // Step 2: Pass the inpu`t into the variable `input`.
        // Our String is `mut`, which stands for mutable so that we
        // can set a value to it later on. One of Rust's code design philosophies
        // is that things are mutable only when they need to be, which reduces the
        // probability of a whole lot of bugs getting through.
        let mut input = String::new();

        // `read_line` returns how many bytes it read. Zero means the input is
        // over: Ctrl-D at a terminal.
        if io::stdin().read_line(&mut input)? == 0 {
            return Ok(());
        }

        // Step 3: Answer.
        println!("{}", session.eval(&input));
    }
}
